# Портфель Т-Инвестиций

Постоянный read-only воркер опрашивает T-Invest API через `invest-go` и записывает состояние в SQL Server. Торговые методы не вызываются. Завершение — Ctrl+C или `SIGTERM`.

## Запуск

Из корня репозитория:

```bash
go run ./cmd/portfolio
```

Для записи нужен `TINVEST_SQL_DSN`. В общей базе `quik-portfolio` должны быть применены Goose-миграции проекта `quik-portfolio`; версии 042 и 043 создают таблицы текущего состояния и истории и удаляют старые таблицы запусков. В проверенной базе применена версия 43.

Профиль и тарифные квоты читаются при старте. Воркер ограничивает запросы по группам методов из `GetUserTariff` с запасом 20% и дополнительно ограничивает суммарную частоту до 40 запросов в секунду. Если метод отсутствует в тарифном ответе, для него действует отдельный лимит — один вызов за 5 секунд. Задачи работают независимо: ошибка одного метода видна в stderr, следующий опрос продолжится по расписанию; при ошибке лимита задача ждёт с увеличивающейся паузой.

Ответы API по умолчанию пишутся в `logs/api-dump.jsonl`; отключить файл можно так:

```bash
go run ./cmd/portfolio --dump ""
```

Дамп начинается заново при старте процесса. Он не содержит заголовка авторизации.

## Периодичность

У каждой задачи отдельная переменная окружения `TINVEST_POLL_<TASK>` с длительностью Go (`30s`, `5m`, `24h`). Значения по умолчанию:

| Задачи | Интервал | Переменная |
|---|---:|---|
| Счета | 5 минут | `TINVEST_POLL_ACCOUNTS` |
| Профиль и квоты | 24 часа | `TINVEST_POLL_PROFILE` |
| Портфель, остатки, лимиты, маржа, операции, заявки, стоп-заявки | 1 минута | `TINVEST_POLL_PORTFOLIO`, `TINVEST_POLL_POSITIONS`, `TINVEST_POLL_WITHDRAW_LIMITS`, `TINVEST_POLL_MARGIN`, `TINVEST_POLL_OPERATIONS`, `TINVEST_POLL_ORDERS`, `TINVEST_POLL_STOP_ORDERS` |
| Последние цены и цены закрытия | 1 минута на метод | `TINVEST_POLL_LAST_PRICES`, `TINVEST_POLL_CLOSE_PRICES` |
| Статусы торгов | 1 минута | `TINVEST_POLL_TRADING_STATUSES` |
| Информация и паспорта бумаг, купоны, события, дивиденды, НКД, риск, расписание, фундаментал, инсайдеры, новости и поиск | 24 часа | `TINVEST_POLL_INSTRUMENT_METADATA`, `TINVEST_POLL_SHARE_PASSPORT`, `TINVEST_POLL_ETF_PASSPORT`, `TINVEST_POLL_BOND_PASSPORT`, `TINVEST_POLL_BOND_COUPONS`, `TINVEST_POLL_BOND_EVENTS`, `TINVEST_POLL_DIVIDENDS`, `TINVEST_POLL_ACCRUED_INTERESTS`, `TINVEST_POLL_RISK_RATES`, `TINVEST_POLL_TRADING_SCHEDULE`, `TINVEST_POLL_FUNDAMENTALS`, `TINVEST_POLL_INSIDER_DEALS`, `TINVEST_POLL_NEWS`, `TINVEST_POLL_INSTRUMENT_SEARCH` |
| Страны и бренды | 7 дней | `TINVEST_POLL_COUNTRIES`, `TINVEST_POLL_BRANDS` |

Например, `TINVEST_POLL_PORTFOLIO=2m` опрашивает портфель раз в две минуты. Лимитер API всё равно может отложить запрос, если доступная квота ниже расписания.

## Хранение

Текущие данные обновляются по ключам счёта, инструмента, заявки или справочника. Успешный полный ответ метода заменяет строки своего набора; ошибка не очищает прежние данные. Операции, купоны, дивиденды, события облигаций, график НКД, сделки инсайдеров и новости хранятся в истории по ключу события и дате события. Первое чтение операций загружает всю доступную через API историю; страницы читаются до конца курсора. После успешной загрузки сохраняется watermark, и следующие опросы получают только свежие операции с перекрытием суток и дедупликацией.

В сервисе нет сущности запуска, к которой привязываются строки. Общие позиции T-Invest остаются в `portfolio.positions` по ключу даты, счёта и инструмента; это дневная история, не идентификатор запуска.

## Настройки

В `.env` или окружении:

- `TINVEST_TOKEN` — токен только для чтения; также поддерживается `TINKOFF_TOKEN`.
- `TINVEST_ENDPOINT` — gRPC адрес. По умолчанию используется боевой контур `invest-public-api.tinkoff.ru:443`.
- `TINVEST_ACCOUNT_ID` — необязательно ограничивает работу одним счётом.
- `TINVEST_CA_FILE` — необязательно указывает PEM дополнительного корня TLS. Если не задан, используется `certs/russian_trusted_root_ca.pem`, когда файл существует.
- `TINVEST_SQL_DSN` — строка подключения к общей базе SQL Server.

Токен и строка подключения не выводятся воркером. Полный токен этой утилите не нужен: он даёт право выставлять заявки.

## Проверка

```bash
go test ./...
```

После применения миграции проверьте вручную, что второй опрос обновил те же ключевые строки, операции за перекрывающийся период не дублируются, ошибка одного метода не останавливает остальные и Ctrl+C штатно завершает процесс.

## Импорт брокерских отчётов

Отчёты T-Invest загружаются отдельным локальным HTTP-процессом. До запуска примените SQL Server-скрипты `migrations/100_tinvest_broker_reports.sql`, `migrations/101_tinvest_report_operation_name.sql` и `migrations/102_tinvest_trade_isin.sql` к той же базе, на которую указывает `TINVEST_SQL_DSN`. Схема миграции 100 обязательна и для `cmd/portfolio`, и для `cmd/report-api`. Скрипт 100 создаёт raw-слой и общие таблицы исполнений, дополняет таблицу операций приоритетом источника и переносит имеющиеся API fills в нормализованные сделки. Скрипт 101 увеличивает длину описания денежной операции для полных примечаний из отчёта. Скрипт 102 хранит ISIN отдельно от тикера, переносит в него уже загруженные ISIN и добавляет индекс для точного поиска. Все скрипты идемпотентны.

Номер из строки `Инвестор` в отчёте необходимо явно связать с `account_id` T-Invest API. После применения скрипта добавьте соответствия в `tinvest.report_account_mapping`:

```sql
INSERT INTO tinvest.report_account_mapping (report_account, account_id)
VALUES (N'<номер из отчёта>', N'<account_id T-Invest>');
```

Запустите API из корня проекта:

```bash
go run ./cmd/report-api
```

По умолчанию он слушает только `127.0.0.1:8082`. Другой loopback-адрес задаётся переменной `TINVEST_REPORT_API_ADDR` в окружении или `.env`. Загрузите один XLSX-файл за запрос:

```bash
curl.exe -F "file=@docs/broker-report-2026-01-01-2026-11-09.xlsx" http://127.0.0.1:8082/api/v1/reports
```

Raw-строки сохраняются до нормализации. Повтор того же файла возвращает прежний результат и не создаёт дубликаты. Исполнения сопоставляются по номеру сделки и части РЕПО; денежные операции — по счёту, типу, времени и сумме. Неоднозначные операции остаются отдельными строками и увеличивают `warnings`. Непустые поля отчёта приоритетнее API; более старый отчёт не перезаписывает более свежий. Если обработка завершилась ошибкой, raw-данные и статус импорта сохраняются; повторная отправка файла с тем же содержимым запускает обработку заново.
